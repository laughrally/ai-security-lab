生成AIと情報漏洩について、中小企業の現場で起きることを書いています
生成AIの「学習させない設定」で防げること、防げないこと
設定をオフにすれば安全、という理解は半分しか当たっていない。設定で消えるリスクと、設定では一切動かないリスクを分けて整理します。
2026-10-27　ChatGPT / 設定
生成AIに社外秘を入れてしまった。最初の1時間にやること
やってしまった後にまずすべきなのは、履歴の削除ではありません。順番を間違えると、後から何も説明できなくなります。
2026-10-27　事故対応 / 個人情報
社内の生成AI利用ガイドライン、最低限これだけ書けばいい
立派な規程を作ろうとして止まるくらいなら、A4一枚で今週から回したほうがいい。そのまま使える文面を置いておきます。
2026-10-27　社内ルール / ひな形
会社が把握していないAIの見つけ方
社員が勝手に使っているAIのこと。禁止令を出すと見えなくなるだけで、なくなりはしません。
2026-10-27　社内ルール / 実態調査
顧客情報を生成AIに入れると、個人情報保護法上どうなるか
入力した瞬間に即違法、という話ではありません。何が問題になるのか、どこで線が引かれるのかを条文に沿って整理します。
2026-10-27　個人情報 / 法令
「うちみたいな小さい会社は狙われない」が通らなくなった理由
狙われるのは情報を持っているからではなく、取引先につながっているから。生成AIはその経路を一段増やしました。
2026-10-27　取引先
生成AIの情報漏洩、実際に報じられていること
サムスンの件が有名ですが、本当に見るべきは「やった本人に悪意がない」という共通点のほうです。
2026-10-27　事例
議事録AI・文字起こしツールの落とし穴
入力している自覚がないまま、社内で一番濃い情報を外に出している。録音ボタンひとつで起きます。
2026-10-27　議事録AI
製造業で図面や仕様書を生成AIに入れる前に
手元にある図面の多くは預かりものです。自社の判断では出せません。ここが他の業種と違う。
2026-10-27　製造業
士業が顧問先の情報を生成AIに入れるとき
顧問先は「先生に話した」つもりで、「先生とAI事業者に話した」とは思っていません。そのずれが問題になります。
2026-10-27　士業
Microsoft 365 Copilot を業務で使うときに確認すること
データは社外に出ません。代わりに、社内で見えてはいけないものが社内の人に見えるようになります。
2026-10-27　Copilot / 設定
「社員教育を実施した」と取引先に示すには何が要るか
対策していることと、していると示せることは別です。実際にやっているのに証明できない会社が多い。
2026-10-27　教育の記録 / 取引先
ChatGPTの「一時チャット」は本当に残らないのか
履歴に出ないのと、送信されないのは別です。守っている相手が違う。
2026-10-27　ChatGPT / 設定
ChatGPTのカスタム指示に、会社の情報を書いていいか
一度書いた文章が、以降すべての会話に自動で付きます。天気を聞いた会話にも。
2026-10-27　ChatGPT / 設定
GPTs（マイGPT）に社内資料をアップロードするリスク
会話を消しても、登録した資料は消えません。そして公開範囲の設定を1つ間違えると、本当に外に出ます。
2026-10-27　ChatGPT
NotebookLMに社内資料を入れていいか
資料を入れないと何もできないツールです。つまり使い始めた瞬間に、判断が必要になります。
2026-10-27　NotebookLM
危ないAIブラウザ拡張の見分け方
「すべてのサイトのデータの読み取りと変更」を許可した拡張は、あなたが開く全画面を読めます。
2026-10-27　ブラウザ拡張
退職者のAIアカウントをどう止めるか
PCも入館証もメールも止めている会社が、AIだけ止めていません。中身は在職中の業務の会話です。
2026-10-27　退職・異動
業務委託・フリーランスの生成AI利用をどう縛るか
社内規程は委託先に届きません。そして渡している機密の量は、社員より多いことがあります。
2026-10-27　委託先 / 契約
採用の応募書類を生成AIで評価していいか
整理させるのと、判断させるのは別です。前者は条件次第で実務に乗り、後者は説明責任が残り続けます。
2026-10-27　採用 / 個人情報
契約書のレビューを生成AIにさせるとき
契約書には必ず相手方がいます。そして契約内容自体を秘密とする条項が入っていることが多い。
2026-10-27　契約 / 法務
プログラムのコードを生成AIに貼るとき
貼っているつもりなのはロジックだけ。実際には接続情報と業務構造が付いてきます。
2026-10-27　開発
クレームメールを生成AIに相談するとき
急いでいるときほど、そのまま貼ります。そして健康被害の記述は最も重い類型です。
2026-10-27　顧客対応 / 個人情報
請求書・領収書をAI-OCRに通すとき
読み取りではなく送信です。そして「人が目視している」工程があることは、あまり知られていません。
2026-10-27　経理 / AI-OCR
翻訳に生成AIを使うとき、海外取引で気をつけること
社内で一番使われているAIは翻訳です。そして中身は、たいてい単価と納期と契約条件。
2026-10-27　翻訳 / 海外取引
社内AIチャットボットの権限設計
失敗する原因は精度ではありません。見せたくない文書を検索の対象から外していないことです。
2026-10-27　社内チャットボット
生成AIの利用ログを、どこまで取るべきか
監視を強めるほど把握できる範囲は狭くなります。直感に反しますが、中庸が一番情報を得られる。
2026-10-27　社内ルール / 労務
生成AIのインシデント報告書の書き方（ひな形つき）
原因分析から書き始めると、事実が推測に引きずられます。先に事実を固定する。
2026-10-27　事故対応 / ひな形
建設業で生成AIを使うとき、現場と事務所で分けて考える
事務所は書類、現場は写真。起きる事故の形が違うので、同じルールではどちらにも効きません。
2026-10-27　建設業
医療機関・クリニックで生成AIを使うときの線引き
診療情報は要配慮個人情報で、守秘義務には罰則があります。一般企業の「機密情報」とは法的な重さが違う。
2026-10-27　医療
不動産業で生成AIを使うとき、物件情報と顧客情報を分ける
メール1通に、物件の特定情報と個人の属性が同時に入ります。そして件数が多い。
2026-10-27　不動産
人事評価のコメントを生成AIに書かせるとき
評価は昇給や処遇の根拠になる文書です。「AIが出した評価です」では合理性の説明になりません。
2026-10-27　人事
プレスリリースを生成AIで書くとき、未公表情報をどう守るか
発表日の1週間前に原稿を貼る。その時点では、未公表の情報を外部に送っています。
2026-10-27　広報
営業リストの作成・整理に生成AIを使うとき
名刺の情報は個人データで、企業サイトの代表電話は公開情報。同じリストに両方が入っています。
2026-10-27　営業 / 個人情報
小売・ECで注文データを生成AIに入れる前に
CSVを1回貼るだけで数千件が対象になります。件数が報告義務の判断に直結する業種です。
2026-10-27　小売・EC / 個人情報
学習塾・教育事業で生成AIを使うときの線引き
扱っているのは未成年の情報で、保護者は「子どものために預けた」と思っています。
2026-10-27　教育事業
運送・物流で生成AIを使うとき
配送先リストは個人情報の一覧です。そして荷物の中身は、荷主にとっての営業情報。
2026-10-27　運送・物流
見積・原価を生成AIに入れてはいけない理由
法令違反にはなりません。報告義務もありません。誰にも怒られない。それでも利益は減ります。
2026-10-27　見積・原価
AIツールの利用申請フローは、どこまで作るべきか
厳しくするほど申請されなくなります。目的は止めることではなく、知ることです。
2026-10-27　社内ルール
社内規程・マニュアルを生成AIで作るとき
ここは向いている使い方です。ただし、そのまま配ると読む側に必ず分かります。
2026-10-27　社内ルール / ひな形
Geminiの個人版とWorkspace版は、何が違うのか
同じ名前でも、データの扱いと会社の管理権限がまったく違います。
2026-10-27　Gemini / 設定
Claudeを業務で使うときに確認すること
長い資料を一度に渡せるぶん、1回の操作で外に出る情報が増えます。
